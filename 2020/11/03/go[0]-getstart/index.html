历史

Go语言（或 Golang）起源于 2007 年，并在 2009 年正式对外发布。Go 是非常年轻的一门语言，它的主要目标是“兼具 Python 等动态语言的开发速度和 C/C++ 等编译型语言的性能与安全性”。golang的 1.13 版本的时候，被gc被重新，将增加内存回收速度（2014-05）。

go install

参数和go build一致，只是将编译结果安装到bin/pkg目录中。go install支持增量编译。如果没有修改，将会直接链接pkg目录中的静态包。编译器用buildid检查文件清单和导入依赖。

在没有mod之前，有些项目都是通过go install来编译工程的，并且将GOBIN环境变量临时修改成发布目录，如果已经用上了mod方式，尽量使用go build来编译工程。

golang <= 1.13 版本

这个版本的golang，使用的是vendor的包管理。

这次解决了一个问题：

问题：

  1. 源代码是 a.com 域名；代码目录下有个 vendor/b.com ； 代码中大量引用了 b.com/common/ 库；
  2. 将代码切到 ${GO_ROOT}/src/a.com/project 编译，将会让 a.com 下的 vendor/b.com 库无法被扫描到；
  3. 解决办法是将 ${GO_ROOT}/src/a.com/project 放到 ${GO_ROOT}/src/b.com/project 目录就可以了；
  4. 还有一个办法，将源代码中 b.com/common/ 修改成 c.com/common/ ；并且将 vendor/b.com 目录修改成 vendor/c.com

是的，Git Submodule 支持指定分支，你可以在添加子模块时指定它跟踪的分支，而不是默认的 HEAD。下面是详细操作：

  1. 添加 Submodule 并指定分支

默认情况下，git submodule add 只会添加一个固定的 commit，而不会跟踪远程分支。要让 Submodule 跟踪特定分支，可以这样做：

步骤 1：添加子模块并指定分支

git submodule add -b my-branch https://github.com/user/dependency-project.git internal/dependency

这里：
• -b my-branch 让 dependency-project 跟踪 my-branch 分支。
• internal/dependency 是存放子模块的路径。

  1. 更新 Submodule 以同步远程分支

默认情况下，git submodule update 只会获取固定的 commit，而不会自动拉取最新的分支。所以，你需要执行：

git submodule update —remote

这会让所有子模块更新到 远程分支的最新提交。

如果你只想更新某个特定的子模块：

git submodule update —remote internal/dependency

  1. 自动拉取最新代码

如果你希望每次 git pull 时，Submodule 也自动更新，可以这样配置：

git config -f .gitmodules submodule.internal/dependency.branch my-branch

然后，在主项目里执行：

git submodule update —remote —merge

这会 自动更新 Submodule 到远程 my-branch 的最新提交。

  1. 提交子模块的变更

当 Submodule 有变更后，你需要在主项目中提交更新：

  1. 克隆包含 Submodule 的项目

如果其他人克隆你的项目，需要执行：

git clone --recurse-submodules https://github.com/user/main-project.git

如果已经克隆了主项目但没有子模块，可以手动初始化：

git submodule update —init —recursive

总结

命令 作用


块跟踪分支
git clone --recurse-submodules <repo> 克隆项目并初始化子模块

这样，你的子模块就能自动跟随远程分支，而不只是固定在某个 commit 了！🚀
如果你想彻底移除某个 Git Submodule，需要清理多个地方。以下是完整的移除步骤：

  1. 取消 Submodule 关联

首先，使用以下命令从 Git 记录中删除子模块：

git submodule deinit -f -- internal/dependency

这里：
• internal/dependency 是你的子模块路径。

这会移除 .git/modules/internal/dependency 目录，并取消子模块的关联。

  1. 删除子模块目录

手动删除子模块的代码目录：

rm -rf internal/dependency

此时，子模块的代码文件已经被删除。

  1. 从 Git 配置中删除 Submodule

编辑 .gitmodules 文件，找到类似下面的内容：

删除该部分的配置，然后保存。

  1. 从 Git 记录中删除 Submodule

从 Git 索引中删除子模块的记录：

git rm --cached internal/dependency

然后提交变更：

git commit -m "Remove submodule internal/dependency"

  1. 清理 Git 残留（可选）

可以执行以下命令，彻底清理子模块的缓存：

rm -rf .git/modules/internal/dependency

  1. 推送到远程仓库

最后，把删除 Submodule 的变更推送到远程：

git push origin main

dlv.path=/Users/solego/go/bin/dlv
